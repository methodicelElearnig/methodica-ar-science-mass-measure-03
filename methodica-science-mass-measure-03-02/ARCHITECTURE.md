## המשכיות דמות נלווית בין סינים (חשוב — שונה במהותו מסיין 1)
בסיין 1, מסך 1 היה TwoOptionSelection שבו הלומד/ת בוחר/ת דמות (pink/boy),
נשמר גם ב-`window.lomdaState.selectedCharacter` וגם ב-
`localStorage.setItem('lomda_selectedCharacter', …)`. **סיין 2 אינו כולל
מסך בחירה חוזר** — הוא רק **קורא** את אותו מפתח `localStorage` באתחול:
```js
let savedCharacter = null;
try {
  savedCharacter = localStorage.getItem('lomda_selectedCharacter');
} catch (e) {}
window.lomdaState = { selectedCharacter: savedCharacter || null };
```
כך שכל מסך עתידי בסיין הזה שמציג את הדמות הנלווית (Companion character
system, ראו `720-templates` → `_global-components.md`) יכול לקרוא
`window.lomdaState.selectedCharacter` בדיוק כמו בסיין 1, בלי לדעת/לשאול
מחדש מה נבחר. **הערה:** אם הלומד/ת פותח/ת את סיין 2 בדפדפן/מכשיר/פרופיל
אחר בלי לעבור דרך סיין 1 קודם (`localStorage` ריק), `selectedCharacter`
יהיה `null` — טרם הוגדר מנגנון fallback לתרחיש הזה (למשל ברירת מחדל, או
מסך בחירה מקוצר); ידרש החלטה כשייבנה המסך הראשון שבאמת מציג דמות.

### שאלה 1 מתוך 2 — מורכבת מ-4 סעיפים (מסכים 7-10)
**`q1SectionResults`/`q1SectionDone(section, outcome)`** — עותק גנרי
נוסף של הדפוס מסיין 1 (שם: `stationBSectionResults`/`stationBSectionDone`,
2 סעיפים בלבד; כאן 4: א/ב/ג/ד). כל סעיף קורא לפונקציה פעם אחת עם
התוצאה שלו (`'success'`/`'fail'`); היא ממתינה **שכל ארבעת** הסעיפים
יירשמו, ואז קובעת: `stationProgress2.q1 = 'success'` **רק אם כולם**
הצליחו, אחרת `'fail'`. נבדק ב-Playwright שני תרחישים: (1) 4/4 נכון →
`qnav-success`; (2) סעיף א נכשל (2 ניסיונות שגויים), ב/ג/ד נכונים →
**`qnav-fail`**, בדיוק כמבוקש (שאלה כולה נכשלת אם סעיף אחד נכשל, גם אם
השאר נכונים).
